# vyakarana — 2.9.x closeout audit

- **Date:** 2026-10-21
- **Version audited:** 2.9.0 (fixes shipped as **2.9.1**)
- **Toolchain:** `cyrius 6.7.15`
- **Scope:** the CLAUDE.md §Hardening step over everything since the
  [2.6.x audit](2026-10-20-2.6.x-closeout-audit.md): 2.7.0's number
  literals (ADR 0026), 2.7.1's string prefixes, `ident_lead`,
  next-byte line rules and heredoc words (ADR 0027), 2.8.0's streaming
  engine (ADR 0028), 2.9.0's compacted blobs, POSIX generator, size
  budget and audit scripts (ADR 0029). The empirical sweeps were re-run
  over the whole library, from `scripts/audit/` for the first time.
- **Method:** three independent read-only reviewers, one per area —
  A: the single-feed scanner work of 2.7.x; B: the streaming engine;
  C: tooling, the grammar loader, detection and the CLI — each working
  on its own copy of the 2.9.0 tag and required to reproduce every
  claim. Then the sweeps, which do not depend on anyone reading the code
  right. **Every finding marked fixed was reproduced on 2.9.0 before the
  fix and re-checked after it, and every test added for one was run
  against the 2.9.0 sources and shown to fail there** (tests that call
  APIs 2.9.0 lacks were checked with the reviewer's probe instead).

**The streaming engine's "linear" claim was the weak spot,** and so were
2.9.0's own audit scripts. ADR 0028's correctness half held — no watch
can change a token — but four inputs made chunked streaming quadratic,
and its one shortcut outside a full scan, the pending-pair fast path,
changed tokens for a prefixed string. The scripts written to make audits
repeatable passed when they checked nothing. The sweeps also turned up
the oldest bug here, from 1.13.2: an indented markdown fence mis-paired
every fence after it.

## Findings — scanner, loader, detection (reviewers A and C, and the sweeps)

### P1-1 — Markdown: an indented or quoted fence closed at the next column-0 fence (1.13.2)

`_ds_find_fenced_close` took the end marker only in column 0, while the
opener matched anywhere. A fence in a list item (`   ```sh` …
`   ````) or a blockquote (`> ```c` … `> ````) ran on to the next
column-0 fence and took its *opener* as the close — every later fence in
the document paired one off, prose highlighted as code and code as
prose. 830 indented or quoted fence lines in 195 of one machine's 7,770
markdown files; the sweep met it as 21 error tokens in a blockquote.
**Fix:** a `compose_fenced` rule's optional `end_indent` — bytes that may
precede the closer on its line; markdown's is space, tab and `>`. The
candidate positions depend only on the bytes, so the no-closer watermark
still holds. A column-0 fence whose body holds an indented ```` ``` ````
line now closes there (CommonMark closes at up to three spaces). ADR
0016 amended. Tests: list item, blockquote, column-0 with an indented
closer — fail on 2.9.0; two every-offset shapes in the chunk fuzz.

### P2-1 — Markdown: fence tags resolved by exact grammar name only

`sh`, `bash`, `cyr`, `js`, `Python` named no grammar, so the body was
one string: 3,679 of 7,607 tagged fences on that machine (`sh` 1,936,
`bash` 1,204, `cyr` 331). ADR 0016's own example tag, `bash`, never
resolved. **Fix:** `registry_find_fence_tag` — the name; else, ASCII
case ignored, the name, a declared `extensions` entry `.tag`, or a
`shebangs` entry (ADR 0025's data). Tests fail on 2.9.0.

### P2-2 — Streaming: a rewritten heredoc delimiter's address became a buffer offset (reviewer A, F1)

The body step (H) handed the drain `load64(e) - src` for the terminator
watch without checking that the delimiter lay in `src`. A delimiter that
quote removal rewrote (`<<"E"OF`, `<<E\OF`) lives in the per-depth
scratch slot; the opener path gated its own fast path on that, the body
step did not. Trigger: two heredocs on a line, the second's terminator
only inside the first body. With the slot above the buffer the watch
compared lines against bytes outside it — never firing (held to finish
or 1 MiB); the reviewer's probe faulted (exit 139). With the slot below,
the drain's `hd_dpos >= consumed` check refused the negative offset and
armed no watch at all, so every later drain re-scanned. **Fix:** with
P2-6 — the scanner reports such a delimiter as offset -1 plus its
address (`_ds_hd_in_src` decides), and the drain watches a copy. The
test asserts mode 1 against the copy (offset -1); 2.9.0 gives mode 1 on
a garbage offset or no watch, depending on the heap.

### P2-3 — Two consumer grammars composing into each other overflowed the stack (reviewer C, P2-1)

`_gp_validate` refuses only a grammar that composes itself; `cya`'s
region routed to `cyb` and back, one recursion per region — `--- ` x
20,000 (80 KB): SIGSEGV. The bundled grammars have no cycle. **Fix:**
`DS_MAX_DEPTH` 32 in `_ds_inner_tb`; deeper bodies degrade to one
string, as for a missing inner grammar. Test: 20,000 nested regions,
covered.

### P2-4 — Memory: the heredoc line index cost 52 bytes a line (mine)

2.8.0's index (ADR 0028) is built over the whole scan buffer on the
first terminator lookup: a 1 MiB newline flood after one `cat <<EOF`
peaked at 59.7 MB (6.4 MB without the opener); a 16 MiB single feed
would take about 0.9 GB. **Partly fixed:** buckets at load factor 1, not
1/2 — 36 bytes a line, 43.3 MB, output identical. The rest (line ends
recomputed, the tab-stripped half built only for `<<-`) is scheduled.

### P3 — fixed

- **P3-a — A heredoc delimiter over 255 bytes was no longer a heredoc**
  (2.7.1; reviewer A, F2): contiguity was judged against the 255-byte
  slot. It is tracked while parsing now; only a rewritten delimiter is
  capped. A 300-byte `<<AAA…` body is one 305-byte string, as in 2.6.2.
- **P3-b — SCSS: a lone `$` was an error token** (2.7.1's `ident_lead`;
  reviewer A, F3). `$` added to the operators.
- **P3-c — Detection reached too far** (the 2.9.1 roadmap's open input;
  reviewer C measured it). `Dockerfile.5.gz` (183 error tokens),
  `Makefile.cmake`, `Makefile.rej`, `Dockerfile.dockerignore` routed by
  `name.<anything>`, and `notaMakefile` by an unanchored ending. The
  suffix must start with a letter and not end in a compression, patch
  or tool suffix; an ending must start the path or follow `/ . - _`.
  Of 239 matching files on the machine, 2 change. Source-highlight's
  `makefile.lang` stays a makefile (ADR 0025 amended).
- **P3-d — `compose_region` without `end_before` was rejected**
  (reviewer C, P3-3), though ADR 0019 defines it (run to EOF) and the
  drain has a hold for it (mode 4), unreachable since 2.5.2. Restored;
  test streams one a byte at a time.
- **P3-e — Keys accepted and then ignored** (reviewer C, P3-4): an
  `ident_lead` byte outside `ident_start`, `number_float` /
  `number_datetime` without `number_decimal`, a blank / line-break /
  letter `number_separator` (`1\n2\n3` became one number). Rejected now.
- **P3-f — Nix floats split** (mine): ADR 0026 left nix out with no
  reason; its own header says it has floats. Opted in.
- **P3-g — ADR 0026 said "one exception"** to its every-token-is-a-union
  rule; `1e5f` (`e5f` → `e5` + `f`) is a second (reviewer A, F5).

## Gate holes — fixed, each shown to fail before the fix

All in 2.9.0's own tooling, found by reviewer C unless noted.

- **G-1 — Every audit sweep passed when it swept nothing.** A missing
  path warned and the empty list passed (`files=0 … fails=0`, exit 0);
  relative paths were resolved after the `cd` to the repo root, so `.`
  swept vyakarana. `audit_list` resolves against the caller and exits 2.
- **G-2 — The blob test could pass with one blob shadowing another.**
  `zz-a` and `zz_a` map to one symbol (the compiler only warns), and the
  test built its paths from the grammars that loaded. The generator
  refuses a collision; the test walks `_grammar_blob_path(i)` and checks
  each blob's grammar is the one registered.
- **G-3 — `check-detect.sh` accepted a route declared in a comment.**
  `decl()` matched the line whole; it strips the comment now. The
  reviewer's `.h++` repro fails.
- **G-4 — `check-size.sh` passed an unreadable binary** (`OK —  bytes`).
- **G-5 — `coverage-sweep.sh` failed files over the CLI's input cap**
  (mine): counted as over-cap now; `stream-sweep.sh` takes them through
  the library.
- **G-6 — `stream-sweep.sh` with FILEs reported false failures under
  dash**: `$(…; echo $?)` inherits `set -e` there and dies before the
  echo. Checked under dash in `ubuntu:24.04`: the old form captures
  nothing, the new one 4.
- **G-7 — Ctrl-C did not stop the scripts**: `trap … EXIT INT TERM`
  cleaned up and let them carry on (an interrupted generator still
  printed `wrote …`). INT / TERM now `exit` (embed, check-size,
  check-detect, smoke, bench-paired, the four sweeps).
- **G-8 — The compactor's "exactly" was not**: where a blank in
  malformed text changes what the loader reads (`tr ue`, `number_ 0x`,
  `[ grammar]`) it compacted it into something read differently. It
  refuses those now; ADR 0029 and the script header say so.

## Findings — the streaming engine (reviewer B)

The reviewer confirmed ADR 0028's "no watch can change a token" half
structurally — every watch returns having committed nothing, or clears
itself and falls through to a full scan — and broke the "linear" half
four ways. The one commit made outside a full scan, the pending-pair
fast path, did change tokens.

### P1-2 — A prefixed triple-quoted string closed at its own opener

`tokenize_stream_drain`'s pending-pair fast path clamped its resume point
to the start marker's length, not to prefix + marker. With at most one
body byte buffered, `buf_len - (elen - 1)` fell inside `f'''` and the next
scan matched the opener's own last quotes: `s = f'''''hello'''` fed a
byte at a time gave `(2,4,6)` and a cascade instead of `(2,4,14)`; also
`b""""""`. Two feeds suffice when the first is drained twice — the pull
adapter drains on every exhausted `_next`. About 190 hits in the
reviewer's fuzz, python only. **Fix:** clamp to the body start. **Gate:**
`fuzz/chunk_invariance.fcyr` drained each shape only twice; every shape
now also runs in 1-, 2- and 3-byte feeds, with three prefixed shapes —
the fuzz fails on 2.9.0.

### P2-5 — An empty `<<''` body was a zero-length token

`cat <<''\n\necho x` emitted `{"kind":"string","start":9,"len":0}` —
the coverage contract requires every token to have a length (the
coverage sweep and the harness both flag it). **Fix:** no token for an
empty body.

### P2-6 — A rewritten delimiter got no working terminator watch

The same root as P2-2 above, seen from the drain: the opener path
refused the fast path for a non-contiguous delimiter (mode 2, a full
re-scan per line), and the body step's garbage offset gave mode 1 on a
wrong address or no watch. `cat <<E\OF` + 960 KB: 10.8 s in 4 KB chunks,
over 300 s in 64-byte ones (`<<EOF`: 34 ms); `cat <<A <<E\OF` with the
terminator at 32 KB emitted nothing until the 1 MiB bound. **Fix:** the
scanner reports such a delimiter as offset -1 plus its address, and the
drain copies it into a per-stream 256-byte buffer (+192) the watch
compares against; a hold that still gets no mode-1 watch now gets mode
2, never none. 0.03 s at 64-byte chunks; the 32 KB case commits at once
(live buffer 16 KB).

### P2-7 — Near-miss markers defeated mode 3

A held fence waited for "```" anywhere, though a fence closes only at a
line start: 1 MB of `s = "```" + x` lines took 36 s in 4 KB chunks, a
100 KB cut 11.6 s in 64-byte ones. A heredoc line held open by a string
waited for `"`, so every `\"` fired. **Fix:** mode 3 carries where its
marker counts (+200: anywhere, at a line start, or after the fence's
`end_indent` bytes) and the string's escape byte (+208); a candidate
that cannot close is passed for good. 0.08 s and 0.01 s.

### P2-8 — The run watch missed two long-tail classes

It refused whitespace in heredoc grammars — 1 MiB of blank lines in
shell, 64-byte chunks: 30 s — and line-rule tokens other than comments
and directives — a 512 KB Zig `\\` string line: 3.4 s. A heredoc's body
starts only after an opener, and then the heredoc hold applies and the
run watch is not armed, so the refusal bought nothing. **Fix:** line-rule
tokens classified by origin, whitespace in every grammar. 0.03 s, 0.01 s.

### P3 — fixed

- **P3-h — The heredoc bound is measured from the group's first opener**,
  not the open body (`cat <<A <<B`, 1.0 MB for A, 120 KB for B trips it);
  the code comment and state.md said "a heredoc body". Documented as a
  group.
- **P3-i — Doc drift:** past the compose bound the held bytes commit as
  that drain read them (for a cyml region its own tokens, not "as the
  outer grammar read it"); `_stream_pair_provisional`'s header described
  a scanner fallback gone since 2.5.2 and sat above another function;
  ADR 0021 gave the stream record as 88 bytes (192; 216 now).

### Gate holes — fixed

- **G-9 — `fuzz/streaming.fcyr` passed cases whose grammar did not load**
  (`_strm_one` returned success); shown to fail with a misspelled name.
- **G-10 — Nothing exercised the 8 MiB compose bound.** A test streams a
  9 MB unclosed `<style>` in 64 KB chunks: no feed error, the buffer
  within the bound, every byte covered.
- **G-11 — `stream-sweep.sh` gained five stress inputs** — P2-6, P2-7

## Scheduled — not fixed here

- **P2-4 (rest) — the heredoc line index at 36 bytes a line.** Line ends
  recomputed from the next start and the tab-stripped half built only
  for `<<-` would make it about 20 (roadmap backlog).
- **P3 — Swift and HCL `t.0.1` lexes as `t . 0.1`** (reviewer A, F4): a
  tuple index after `.`. Rust does the same deliberately (rustc's lexer;
  a test holds it); for Swift the reviewer recalled, without checking,
  that its lexer reads `0 . 1` — a per-grammar choice once verified
  (roadmap backlog, number shapes).
- **Python 3.14 template strings** `t"…"` are not in python's prefixes
  (reviewer A, noted as out of ADR 0027's list) — roadmap backlog.

## Not defects / kept

- **Two Rust files with `r#"…"#`** surface error tokens — ADR 0027's
  documented gap, now stated in state.md's known limits (which claimed
  no error tokens).
- **LuaJIT's `dis_*.lua` use `!=` and `?:`**, a CSS template has
  `$width`, a `.json` starts with `#`, bison and flex templates are m4,
  Guile's compiled objects end in `.go`, pacman templates in `.proto`:
  error tokens are right.
- **A ```` ```cyrius ```` sample using `/* */`** (libro's guide): Cyrius
  has no block comments — `cycc` rejects one (`unexpected '/'`).
- **Source-highlight's `makefile.lang`** still routes to makefile; `.lang`
  is one program's convention (ADR 0025 amended).
- **A heredoc group over 1 MiB fed in chunks** tokenizes differently past
  the bound — documented, and verified to start exactly where the hold
  passes it.
- **A column-0 fence whose body holds an indented ```` ``` ````** now
  closes there; CommonMark closes at up to three spaces, and the
  scanner tracks no containers — the trade for P1-1.
- **The corpus snapshot of vidya's `dependencies.cyml`** (10.6 KB) is
  kept although vidya's grew to 42.5 KB: the new one is clean (zero
  error tokens, 42,542 split offsets) and swept by the mutation fuzz and
  the coverage sweep; in the corpus it would double the every-offset
  sweep's runtime.
- **The compactor and the loader can still disagree on other malformed
  text** (reviewer C's case c12: a string where a key belongs) — the
  record comparison over every bundled grammar is the gate.
