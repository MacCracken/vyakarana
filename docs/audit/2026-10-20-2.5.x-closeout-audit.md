# vyakarana — 2.5.x closeout audit (P(-1) hardening sweep)

- **Date:** 2026-10-20
- **Version audited:** 2.5.1 (fixes shipped as **2.5.2**)
- **Toolchain:** `cyrius 6.7.15`
- **Scope:** the full CLAUDE.md §Hardening step — code audit,
  refactor where the code asked for it, hardening, optimization and
  a security sweep — over every source file, every grammar, the
  gates themselves, and the docs.
- **Method:** four independent read-only reviews, one per subsystem
  (scanner + tokenbuf; streaming `tokenize.cyr`; grammar loader +
  shell oracle; CLI / detect / LSP / themes), plus a line-by-line
  cross-check of all 46 grammar headers against their bodies. Then
  empirical sweeps that do not depend on anyone reading the code
  right (below). **Every finding marked fixed was reproduced before
  the fix and re-checked after it**; review claims that did not
  reproduce are recorded as such.

> **Why now.** The last full audit was 2.3.4's (2026-08-20). Since
> then: 2.4.0's streaming rework, three toolchain jumps (6.5.32 →
> 6.6.2 → 6.6.20 → 6.7.9 → 6.7.15), 2.5.1's shebang rewrite and
> stdlib trim. None had an audit.

## P1 — Fixed

### P1-1 — `vyk --theme` wrote raw terminal control bytes from the file

`emit_themed` wrote every token's source bytes with a bare `print`.
A file holding `ESC ] 0 ; PWNED BEL` retitled the terminal window,
`ESC [ 2 J` cleared the screen, C1 controls (`C2 9B`, raw `9B`) and a
bare CR passed through — under every theme, `none` included (which
also never writes a reset, so attacker colour state outlived `vyk`).
The 2026-04-23 audit had ruled terminal injection out because "source
bytes never appear directly in stdout"; `--theme` (1.10.0) broke that
premise and no later audit re-rated it.

**Fix** (`src/main.cyr`): `_tty_unit` classifies each byte unit with
real UTF-8 decoding; `_tty_print_safe` writes safe runs in one
`print` and unsafe units as visible escapes — caret notation for C0 /
DEL / bare CR (`^[`, `^M`, `^?`), `\xHH` for C1 in either encoding.
Valid UTF-8 is untouched (a naive 0x80–0x9F filter would corrupt
`€` = E2 82 AC); overlong E0 / F0 forms are not treated as sequences
so an overlong C1 falls apart and is caught; a sequence split across
two tokens is carried, not re-judged.

**Verified:** the OSC / CSI fixture renders as `^[]0;PWNED^G^[[2J`
under all three themes, `none` output holds zero ESC; **all 48
corpora are byte-identical to source under `--theme=none`**; C1
split across two error tokens (`C2`|`9B`) renders once as `\x9b`;
`é` and `€` split across 2 and 3 tokens render intact. Smoke group
added; it fails against 2.5.1.

### P1-2 — Streaming: char literals split at a chunk boundary

`_stream_max_marker` — the hold-back window that keeps a token
starting near the buffer end from being committed half-seen —
measured operators and rule markers but not `char_literal` (up to
12 bytes). `c = '\n';` fed as `c = '\n` + `';` failed the literal
shape, fell to the `'` operator, and committed it. Failed on c,
ocaml, julia, crystal and both asm corpora; synthetic `'中'` failed
in rust, java, cpp, kotlin, go.

**Fix:** `best = max(best, DS_CHAR_LITERAL_MAX)` for char-literal
grammars; the constant lives beside the scanner so the two cannot
drift. **Verified:** every-offset split clean on all six corpora.

### P1-3 — Streaming: strings closed on an escaped quote (2.3.4's P1-3, by two more paths)

The 2.3.4 back-off over a trailing escape run existed on the
"still pending" path only. Two other paths committed an escaped
quote as a close:

1. **First-set pending path** — resume was `p_len - (elen - 1)`
   with no back-off.
2. **`_stream_is_trailing_complete`** — the real culprit on the
   corpora: a buffer ending `"…\"` holds a string the scanner left
   unterminated, but its tail *looks* like the close marker, so it
   was committed as a finished string and every quote after it
   flipped parity. json `{"a":"x\"y"}` split after `\"`.

**Fix:** the same back-off on path 1; on path 2 the close marker
counts only if an EVEN run of escape bytes precedes it inside the
body (the scanner applies escapes left to right). **Verified:**
json, toml, csharp, kotlin, php, swift every-offset clean.

### P1-4 — Streaming heap grew 12–24× the input

Every drain allocated a fresh scratch tokenbuf; the bump allocator
never frees. 8 MB fed → 195 MB heap (rust), 97 MB (json, shell),
independent of chunk size — so ADR 0021's 4 GiB-per-stream contract
was unreachable in practice (~50–100 GiB of heap).

**Fix:** one scratch tokenbuf per stream (record +8 bytes, opaque),
reset per drain via a private `_tokenbuf_reset`. **Verified:** 8 MB
→ 105 KB (rust, 4 KB chunks), 56 KB (json, shell); with 64 KB
chunks growth is **3,078,656 bytes flat at 8, 16 and 32 MB**.

### P1-5 — Any JSON document with a decimal number exited 1

`.` was in neither JSON list, so `0.1` emitted `TK_ERROR` — 4 of the
sweep's JSON files, and the header claimed floats split "not as an
error". **Fix:** `.` added to JSON's operators (a float now splits
`0` `.` `1` like every other grammar's; a real float token is
roadmap work).

## P2 — Fixed

- **P2-1 `lsp_kind_from_standard_index` mapped indices 14–22 wrong.**
  The code, its comment table and ADR 0012 gave three orderings, none
  the LSP 3.17 `SemanticTokenTypes` order; comments came back
  TK_KEYWORD, strings TK_COMMENT, … The tests pinned the code's
  values. Fixed to spec (+ 3.18 `label`); the test now asserts the
  index path equals the name path for all 24 types. ADR 0012 amended.
  No consumer calls it yet (cyim / thoth vendor it).
- **P2-2 stderr sanitizer passed C1 controls** (`C2 9B`, raw `9B` in a
  path). Now judged by the same `_tty_unit`.
- **P2-3 `has_grammar(0)` / `tokenize_stream_new(0)` segfaulted** —
  and `detect_language()` returns 0 for an unknown path, so
  `tokenize_stream_new(detect_language(path))` was the natural crash.
  `registry_find_by_name(0)` now returns 0.
- **P2-4 the grammar parser accepted incomplete rules that crashed
  the scanner** — `pair` without `end`, `words` without `words`,
  `compose` without `inner`, `words` + `inner` (slot-40 type
  confusion), empty `start`, unknown `match`, `ident_start` without
  `ident_cont`, `unicode_ident` without tables (crashed on the first
  non-ASCII byte of untrusted input), empty list entries, a compose
  rule naming its own grammar. `_gp_close_rule` / `_gp_validate` now
  reject them: **13/13 crafted crash grammars rejected, 46/46 bundled
  grammars load**.
- **P2-5 compose openers with no closer were quadratic** — each
  opener re-scanned to EOF. 1 MiB of `<style>`: killed at 300 s;
  1 MiB of ``` x```a ``` lines: 282 s. Per-call "no closer from here"
  watermarks on compose, compose-fenced and the no-LF scan, keyed by a
  per-call generation so nested calls and the streaming drain's
  reused buffer can never see a stale mark. **1.7 s and 2.1 s**;
  outputs identical to 2.5.1 where it finishes (57 KB: 1.62 s →
  0.10 s).
- **P2-6 a `#!` line mid-stream came back TK_PREPROCESSOR** after the
  rolling buffer compacted (buffer offset 0 ≠ file offset 0). The
  drain now tells the scanner when its buffer is not the file start.
- **P2-7 first-match operator shadowing** — 10 entries in 5 grammars
  were unreachable: php `===` `!==`; crystal `<<=` `>>=` `&&=`
  `||=`; ruby `&&=` `||=`; julia `>>>`; powershell `-isnot`. Reordered;
  a test now enforces it over every loaded grammar (shown to fail with
  2.5.1's php).
- **P2-8 CYML had no `"""` / `'''` strings** — seven vidya field-note
  documents (`content = """…"""`, 148 in one file) exited 1. TOML's
  ADR 0008 rules ported.
- **P2-9 a CYML body ended at any line starting `[`** — links,
  references, `[base, base+size)` in prose; the rest of the body was
  lexed as TOML (vidya `types.cyml`: ~14 KB). `end_before` is now
  `\n[[`: across 35 real CYML files a body was followed by `[[` 663
  times and by `[table]` 0 times, while 21 body lines began with `[`.
  Trade-off documented in the grammar.
- **P2-10 the cyrius grammar had char literals off**, though Cyrius
  has them (`'"'`, `'\n'`, `'\''` all compile and evaluate) and real
  code uses them; `'"'` emitted TK_ERROR and opened a runaway string.

## P3 — Fixed

- Char-literal shapes widened: `'\033'` (octal — C's ANSI escapes),
  `'\uXXXX'`, `'\UXXXXXXXX'`, `'\u{…}'` (Rust's emitted TK_ERROR).
  ADR 0010 amended.
- Missing operators: OCaml `::` `;;`, Ruby `::`, SCSS `==` `!=` `<=`
  `>=`.
- `.zsh` not detected (6/6 sweep files exited 4).
- `vyk --handcoded` stopped at the first NUL (`strlen`): covered 6 of
  11 bytes and exited 0.
- `tokenize_stream_new` ignored allocation failures; `_next` after
  `_free` segfaulted; the fast path over-counted `emitted`.
- Compose: unchecked `tokenbuf_new` / `alloc` (NULL write under OOM);
  a fresh inner tokenbuf per match (1 MB of `<style>a</style>` took
  57.8 MB) — now one per nesting depth.
- Grammar parser: a `#` comment holding `"` or `[` swallowed the
  following keys / the rest of the file; an unknown `[section]` kept
  the previous one (and overwrote the last rule).
- `grammar_load` copied every blob into a 32 KiB buffer because "the
  parser writes NUL terminators in place" — it never writes to its
  input; ~1.5 MB of never-freed heap at bootstrap. Parsed in place.

## Scheduled — not fixed here

Each is placed in a pinned release in `docs/development/roadmap.md`.

- **Shell `#` mid-word starts a comment** (`${#arr[@]}`, `${x#p}`,
  `${x##*/}`) — in the shipped corpus. Needs a line-rule boundary
  option (ADR) and the hand-coded oracle in lockstep. Also: heredoc
  bodies, `\"` outside quotes, `$1`.
- **Streaming re-scans a long non-pair token per drain** — a 512 KB
  line comment in 64-byte chunks takes 4 s. Needs the pending fast
  path generalised beyond pair rules.
- **`number_float`** — floats and exponents as one token (JSON,
  python, rust, …; TOML datetimes). Token boundaries change → minor.
- **Write failures exit 0** (`vyk > /dev/full`); CLI messages for
  empty / bogus `--language=`; `--export-theme` flag order; no stdin.
- **Grammar gaps surfaced by the header cross-check:** PHP 8
  `#[attr]` swallowed by the `#` comment rule; ruby / crystal `@@x`;
  makefile `$<` `$^`…; css `-` unreachable; `extensions` arrays are
  never read (detection is hardcoded; `.asm` `.hh` `.csx`
  `.properties` `.phtml` listed but unrouted).
- **`scripts/embed-grammars.sh` is gawk-only** (`gsub` backslash
  doubling is a no-op under POSIX awk; `grep -P` check passes silently
  where `-P` is absent).
- Compose-grammar chunk invariance and residual O(N^1.6) compose
  drains (pre-existing, unchanged).

## Not reproduced / not defects

- "A `[[rules]]` `compose` comment says fall through to the next
  rule, the code returns" — true, but only reachable with two compose
  starts sharing a prefix (no bundled grammar). Comment corrected.
- BOM before `#!` is not detected — the kernel would not honour it
  either; documented rather than changed.
- The dark theme export's hex values differ from xterm's ANSI RGB —
  deliberate editor colours; the "Mirrors" comment was corrected,
  values kept (changing them would change every exported theme).

## Clean checks

- No out-of-bounds read or write found by review in any file, and
  none by the guard-page fuzz (~25,500 scanner inputs; 200k detect
  inputs; short paths against leading and trailing guards).
- Poison A/B over 1,577 real files: no redzone overwrite, no
  fill-dependent output.
- Coverage invariant held on every one of 3,846 real files, both
  versions.
- tokenbuf growth sound (capacity always a multiple of 12; data
  pointer re-read after every grow); `load32` zero-extends; offsets to
  2³²−6 round-trip; feed errors leave the stream unchanged; API misuse
  (feed after finish, double finish, `free(0)`, double free) safe.
- NDJSON always valid JSON; theme exports parse with `json` /
  `tomllib` / `plistlib` for all 9 format × theme combinations.
- The grammar parser's output for all 46 bundled grammars matches a
  `tomllib` reference parse exactly.
