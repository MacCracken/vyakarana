# vyakarana — 2.9.12 closeout audit

- **Date:** 2026-10-27
- **Version audited:** 2.9.11 (fixes shipped as **2.9.12**)
- **Toolchain:** `cyrius 6.7.18`
- **Scope:** the CLAUDE.md §Hardening step over the 2.9.x arc since the
  [2.9.x audit](2026-10-21-2.9.x-closeout-audit.md) (2.9.1):
  - 2.9.2 the 6.7.18 pin;
  - 2.9.3 literal data gaps;
  - 2.9.4 the heredoc line index;
  - 2.9.5 computed closers and Ruby / PHP heredocs (ADR 0030);
  - 2.9.6 symbol-shaped string prefixes;
  - 2.9.7 number shapes (ADR 0026);
  - 2.9.8 `detect_language_registered` (ADR 0031);
  - 2.9.9 nasm, mdx, lean;
  - 2.9.10 open compose regions that stream (ADR 0032);
  - 2.9.11 documents for incremental retokenization (ADR 0033).

  The empirical sweeps were re-run over the whole library, with
  `edit-sweep.sh` for the first time.
- **Method:** as the 2.9.x audit.
  - Four independent read-only reviewers, one per area: A, the
    single-feed scanner and grammar data; B, the streaming engine; C,
    documents; D, the loader, detection, tooling, CI and docs. Each
    worked on its own copy of the 2.9.11 tag and was required to
    reproduce every claim.
  - Then the sweeps, which do not depend on anyone reading the code
    right.
  - **Every finding marked fixed was reproduced on 2.9.11 before the
    fix and re-checked after it, and every test added for one was run
    against the 2.9.11 sources and shown to fail there.**

**Two of the arc's own changes were the weak spot.** 2.9.10 ran an
unclosed markdown fence to the end of the input "as CommonMark reads it".
That holds only for a fence CommonMark itself opens, and vyakarana opens
fences CommonMark does not. Because no error token appeared, the release's
error-count A/B passed it. 2.9.10's region mode also missed a fence's
closer in a stream after a Lua comment. Both are undone (fences are decided
by their closer again) and the A/B now compares largest tokens. 2.9.11's
documents grew a checkpoint per insert and differed from one feed past the
1 MiB heredoc bound. And 2.9.5's inline raw-string rules had cost Rust
tokenization 16 %, unnoticed for six releases because nobody benchmarked
against the arc's start.

## Findings — single-feed scanner and grammars (reviewer A)

### P1-A1 — An unclosed markdown fence swallowed the rest of real documents (2.9.10)

2.9.10 (ADR 0032) ran a `compose_fenced` body with no closer to the end
of the input. 52 of 5,768 markdown files under `~/Repos` and
`/usr/share/doc` had a fence that 2.9.11 ran to the end. A CommonMark
parser (micromark) closed every one of them earlier:
- 18 opened on a mid-line "```";
- 6 were fences in list items or blockquotes, which CommonMark ends with
  their container;
- 28 opened where an inline code span crossing blocks had already shifted
  the pairing.

agnosai's `CHANGELOG.md` largest token went from 28,942 to 299,948 bytes,
and none of the 52 had an error token. **Fix:** a fence with no closer is
no fence again, as through 2.9.9. It is held in a stream until a closer
arrives. Over the reviewer's list the count goes from 77 open-to-EOF
fences on 2.9.11 to 0. ADR 0032 and ADR 0016 are amended. Tests: three
2.9.10 assertions rewritten, one list-item case added; they fail on
2.9.11.

### P1-A2 — MDX `import` / `export` blocks ended only at a literal `\n\n` (2.9.9)

With CRLF line ends, or a blank line holding spaces, the block never
ended, and the rest of the document was JavaScript (`It's` opened a
string). **Fix:** a new `compose_region` option, `end_blank = true`. The
region ends before a line break followed by a line of only spaces, tabs
and CR. It is searched alike in a single scan and in region mode (kind
5). MDX uses it. ADR 0019 is amended. Tests, CRLF and spaces: fail on
2.9.11. Two chunk-fuzz shapes cover it.

### P2-A3 — The heredoc line index was quadratic when a delimiter shared a crowded bucket (2.8.0)

A failed lookup walked every later line in its bucket. PHP's leading-
identifier key is empty for every `$x = …` and `}` line, and `BAK` hashes
to that bucket below 65,536 lines. 40,000 unterminated `<<<BAK` openers
took 14.5 s (0.29 s for a non-colliding delimiter); the shell case took
2.6 s.

**Fix:** lines are chained by key, not by bucket. A lookup compares the
bucket's distinct keys (usually one), then walks only its own key's
lines from a per-key cursor. The cursor distinguishes "unset" from
"passed", so an exhausted key's chain isn't walked again. That takes
0.38 s and 0.09 s, with byte-identical tokens on every heredoc corpus and
shape. Memory is about 4 bytes a line more.

Distinct keys crafted to collide modulo the bucket count remain
quadratic, now in the build rather than the lookup. The hash is unkeyed
and the stdlib offers no portable random source. A stress input
(`hd_collide.php`) is in `stream-sweep.sh`.

### P2-A4 — A heredoc delimiter cut off by the buffer's end reused the last parse's pointer (2.9.5)

`_ds_hd_parse_ident` and `_ds_hd_parse_delim` returned "undecided" before
setting `_ds_hdd_*`, and the opener check hashed through whatever the
previous parse had left. That could be a pointer into an earlier caller's
freed buffer. The reviewer's probe, run on 2.9.11 after the first buffer
was unmapped, got SIGSEGV in ruby, php and shell. **Fix:** both parsers
clear the pointer on entry, and the caller reads the fields only when
they were set. Test: the stale watch shows on 2.9.11 (`hold_fast` 1) and
not now.

### P2-A5 — A JS / TS regex's `\/*` opened a block comment (2.9.3)

`/^\/*|\/*$/` made the next lines one comment: 29 such comments in 19 of
4,000 node_modules files. **Fix:** `\/` is an operator in javascript and
typescript, so the operator step claims it before `/*` or `//` can start a
comment. In the 13,619-file A/B, 43 JS/TS files change, and each first
change is that operator. Test fails on 2.9.11.

### P2-A6 — C#: after a doubled quote, a verbatim string read on with escapes (2.9.6)

`@"Path: ""C:\dir\"""` became three strings, the last running to the end
of the file. ADR 0027 had promised "all string" at least. **Fix:** a raw
symbol-prefixed string carries on past each doubled quote, raw, as C#
reads it. In streaming:
- a verbatim string closed on the buffer's last byte is neither settled
  nor pended;
- the pending fast path continues past `""` itself.

That holds at every offset, every pair of offsets and in 1–7 byte chunks.
2.9.6's test for the old reading is updated; the new test fails on 2.9.11.

### P2-A7 — NASM hex numbers with an `h` suffix split — *not fixed, documented*

`0Dh` gives `0` + `Dh`, and `0B800h` gives `0B` + `800h`. A digit-led hex
run settles only at its `h`, so a stream needs unbounded number lookahead
to match one feed. It's a known limit in state.md, worded more exactly
than 2.9.9's header was.

### P3 — fixed

- **A8 — Lean projections** (`h.2.2`) read as floats: `number_tuple_index`
  is on, as for Swift.
- **A10 — Heredoc keys the loader accepted but that did nothing:**
  - an inline rule whose `repeat` byte is its `open`'s first byte;
  - `term_rest` without `indent_by = "blanks"` and `delim = "ident"`;
  - a quoted bool (rejected by D9's bool check).

  All are rejected now. ADR 0030's `delim = "ident"` text now says it
  takes bytes 0x80 and above, as the code always did.

### P3 — documented, not scheduled

- **A9 — An MDX expression ends at its first `}`.** In `{`a ${b} c`}` that
  is inside the template literal; the trailing backtick then opens a
  markdown code span. This was documented; the consequence is now stated.
- **A11 — Number shapes that differ from the reference lexers:**
  - Rust `1.e5` and `1.f32` are one number (rustc rejects both);
  - Python `1..real` and JS `1..toString()` read `1` `.` `.`;
  - JS `a?.5:1` reads `?.` `5`.

## Findings — the streaming engine (reviewer B)

### P1-B1 — In a stream, a fence's closer was missed, or a mid-line "```" taken for it (2.9.10)

Region mode kept a fence's line-start state at the end-marker search
point. The inner drain may commit past that point: its limit is the
earliest tail that could begin the marker, which can lie further on. The
state was then not carried over the dropped bytes. After a Lua `--`
comment had committed through its line break, the closer was read as
mid-line; the rest of the document came back as Lua, and later fences
paired one off. The same happened in MDX, with CRLF, and in Julia.

The reviewer's fix carried the state through compaction. With A1, fences
no longer enter region mode at all, so the fence-only code is removed.
The reviewer's shapes and 72 wrapped corpora pass at every offset
(108 files, 0 fails). A Lua fence shape is in the chunk fuzz (G1).

### P2-B2 — A pending string ending in a run of escape bytes was re-scanned every drain (2.5.2)

`x = "` + 1 MB of `\` in 64-byte chunks took 31 s; the same shape was slow
in C, JS and a fenced body. **Fix:** the pending search resumes where it
stopped, which is always on an escape pair's boundary. That replaces the
2.5.2 back-off over the run, and takes 0.01 s.

### P2-B3 — A long shebang line got no run watch

`#!` + 1 MB in 64-byte chunks took 11 s. A shebang line is now watched
like a line rule; it takes 0.02 s.

### P2-B4 — `tokenize_stream_discard_consumed` moved the whole staging each call

Called after every `_next`, 256 KB of python took 15.8 s and 200 KB fed
in one piece 43.8 s (the reviewer's figures; my repeat, 256 KB in 64 KB
feeds: 98.5 s, 0.13 s after). **Fix:** dropped tokens are counted behind the cursor
and moved out only once they are half the staging, which is amortised
O(1) per token. `tokenbuf_drop_front` also moves 8 bytes at a time. The
behaviour is unchanged, and a test pins it.

### P3 — fixed

- **B5:** a number of `_1` separators that every feed ended inside left
  two tokens and no run watch: 23 s for 512 KB, 0.03 s now.
- **Q1:** a region's first body commit inherited the opener's last bytes
  as look-behind. A single feed's nested scan has none.

## Findings — documents (reviewer C)

### P2-C1 — Checkpoints piled up under inserts (2.9.11)

25,000 one-byte inserts, never undone, into a 161 KB file took the
checkpoints from 40 to 23,034, memory from 5 to 35 MB, and an edit from
0.84 to 2.4 ms. Typing 5,000 characters at one cursor added 3,585.
ADR 0033's "memory does not grow" had been measured with edits and their
undos. **Fix:** an edit drains at the next moved old checkpoint when it is
within half an interval past the grid point, and saves none within half
an interval of the last. The checkpoints stay at 40, memory at 5.3 MB,
and the last edit takes 0.94 ms. Test fails on 2.9.11.

### P2-C4 — A document differed from one feed past a hold's bound (2.9.11)

A 1.17 MB heredoc gave 540,011 tokens against one feed's 11. A document
always streams, so its users could not avoid the bound. **Fix:** a stream
records a hold that passed its bound (record +280). A document that saw
one tokenizes the text in one feed, keeping only the first checkpoint, up
to `VYK_STREAM_CAP`. ADR 0033 is amended. Test fails on 2.9.11.

### P3 — fixed

- **C5:** `tokenize_doc_changed_*` on a null document, and `set` / `edit`
  on a freed one, crashed. They return 0 / `VYK_ERR_OVERFLOW` now, as the
  stream API does. After a failed set, the changed range is reset.

## Findings — loader, detection, tooling, docs (reviewer D)

### P1-D1 — `grammar_load` crashed on an unquoted `match` value

`match = line`, or `match =` at the end of a file, passed a null string
to `streq`. The loader fuzz hit it 906 times in 240,000 mutants, and
owl's user overlay loads user grammars. **Fix:** a string key given no
quoted string, or a bool key given anything but `true` / `false` (D9),
rejects the grammar. The `match` handler also guards the null.

### P2 — fixed

- **D2 — The `.asm` GNU-as / NASM vote lost on GNU as's commonest
  idioms.** NASM's `section .` matched inside `.section .text`, and
  `.global` scored nothing. 503 of the host's 1,417 non-Go GNU as files
  voted NASM as `.asm`, among them 84 % of AArch64 files. The vote now
  counts line-start directives on both sides: 66 still vote NASM, files
  with nothing decisive in them, and all 83 NASM files stay nasm.
  ADR 0015 is amended.
- **D3 — Since 2.9.9, ```` ```asm ```` fences tokenized as NASM,** and
  AT&T bodies came back as error tokens, though 2.9.9 claimed unchanged
  output for markdown. A fence tag no longer resolves through an
  extension the content decides between grammars (`.asm`), so the body is
  one string, as through 2.9.8. A ```` ```nasm ```` fence is still NASM.
- **D7 — Three grammar shapes the loader accepts made a stream differ
  from one feed:**
  - **(a)** a multi-byte line `start` with `followed_by`: the marker
    window now counts the next byte;
  - **(b)** a line start that begins a pair's start: line rules run first,
    so such a token is never pended as a pair;
  - **(c)** a pair whose `end` begins with its escape byte: rejected; it
    could never close.

  The bundled grammars have none of them; consumer grammars may. The
  tests run byte feeds of 1–7 against one feed.

### P3 — fixed

- **D8:** `detect_language(0)` and `detect_language_combined(0, …)`
  crashed. They return 0, or the content's route.
- **D9 — The loader accepted values that mean nothing or something
  else:**
  - an empty `filenames` / `extensions` / `shebangs` entry, which matched
    every path;
  - an extension without its dot;
  - a non-bool bool;
  - `end` on a compose_region, or `end_before` on another type (each was
    read as the other).

  All reject the grammar.
- **D11 — Doc and tooling drift:**
  - the authoritative public list in `src/tokenize.cyr` lacked
    detection, `grammar_load`, `registry_add` and the token API;
  - the `.asm` vote was missing from the man page, the detect header,
    the consumer guide and ADR 0031 (a second designed difference);
  - "49 corpora" (52), the blob size, and the manifest table without
    `src/tokenize_doc.cyr`;
  - the guide's stale date;
  - `version-bump.sh` claimed a CHANGELOG header it had not inserted and
    did not cd to the repo root.

  All are fixed.

### P3 — documented, not scheduled

- **D10 — Common fence-tag aliases stay one string** (`c++`, `tsx`, `jsx`,
  `jsonc`, `shellscript`, `golang`, `make`).

## Findings — benchmarks and dead code (mine)

### P2 — `tokenize/rust-small` 16 % slower since 2.9.5

The arc-wide paired benchmark (2.9.0 against 2.9.11) showed
`tokenize/rust-small` +21.3 %, over CLAUDE.md's 20 % line. Bisecting by
release put 16.3 % in 2.9.5: step 1b walked a grammar's inline heredoc
rules at every token position, and Rust has three. **Fix:** a per-scan
bitmap of the bytes an inline opener can begin with. The row is now
−12.7 % against 2.9.11 and +4.6 % against 2.9.0.

### P3 — the inline rules' `tag` accessor was dead

The scanner inferred tag mode from a missing `repeat`. Validation makes
the two equivalent, so the scanner now reads the declared flag.

## Gate holes — fixed, each shown to fail before the fix

- **C2 / C3 — Restoring a checkpoint's look-behind, and comparing its
  second byte, were checked by nothing.** Mutants that dropped either
  passed the fuzz and the suite, and the reviewer's exhaustive probe found
  thousands of wrong results under them. Two unit tests pin them (shell
  `${#x}`, Swift `..0.5`). The fuzz edits 16 short texts at every
  checkpoint spacing 1–12, on fresh and chained documents.
- **C6 — The changed range was checked for soundness, not size.** A
  document reporting the whole re-scan passed. The fuzz now holds every
  edit's and undo's range to its exact minimum.
- **D4 — CI's distlib step diffed the bundle and not its `.deps`
  sidecar.** It runs `cyrius distlib --check` now.
- **D5 — `poison-ab.sh` passed when both legs crashed alike.** A signal in
  either leg fails it now.
- **D6 — Every sweep exited 0 having checked nothing**, when no file had a
  grammar. Each exits 2 now.
- **`check-detect.sh` exempted whole sniff functions**, so a planted
  route in one passed. Each sniff may return only the grammars it decides
  between. A planted `return "rust"` fails it.
- **The shipped (DCE) build was never smoke-tested.** release.yml now
  smokes it before packaging.
- **G-A1 — The single-feed A/B counted error tokens and missed A1.** The
  new `scripts/audit/ab-sweep.sh` reports each changed file's largest
  token too.
- **G-A2 — No MDX test had CRLF or a blank line of spaces.** Tests and
  two chunk-fuzz shapes do now.
- **G-A3, G2 — No stress input exercised a colliding heredoc delimiter,
  an escape run, a shebang line or a separator-run number.**
  `stream-sweep.sh` has all four. Each took 10–29 s on 2.9.11, over its
  10 s limit.
- **G1 — No shape had a fence body ending in a token that commits
  through its line break.** The chunk fuzz has one.

## Not defects / kept

- **The 28 coverage-sweep files with error tokens** are triaged below the
  sweep table: invalid input, or documented limits.
- **The pending-pair and watch comparisons in a document's resync** guard
  fields ADR 0028 shows never change a token. Mutants that drop them fail
  no gate, and none can. They are kept so a resync rests on plain state
  equality.
- **D7's shapes** are fixed or rejected rather than documented, because
  consumer grammars reach them.
