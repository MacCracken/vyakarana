# vyakarana — 2.6.x closeout audit

- **Date:** 2026-10-20
- **Version audited:** 2.6.1 + the 2.6.2 detection work (fixes shipped
  as **2.6.2**)
- **Toolchain:** `cyrius 6.7.15`
- **Scope:** the CLAUDE.md §Hardening step over everything 2.6.x
  added since the [2.5.x audit](2026-10-20-2.5.x-closeout-audit.md):
  2.6.0's `start_after` line rules, `heredoc` rule type and the
  drain's hold / watch / last-byte machinery; 2.6.1's checked stdout
  writer and argument parsing; 2.6.2's detection routes and
  `scripts/check-detect.sh`. The empirical sweeps were re-run over
  the whole library, not only the new code.
- **Method:** three independent read-only reviews, one per area
  (scanner heredoc / `start_after` + loader + shell oracle; streaming
  hold / watch; CLI + detection), each required to reproduce every
  claim. Then the sweeps below, which do not depend on anyone reading
  the code right. **Every finding marked fixed was reproduced before
  the fix and re-checked after it**, and every gate added for it was
  run against the pre-fix sources and shown to fail there.

**2.6.0's heredoc streaming was the weak spot.** Its ADR (0023) was
right about what the hold must guarantee; the implementation missed
three ways the guarantee breaks — a check that looked back only to the
buffer start, a fast path that skipped the bound, and "resolved" judged
per opener when bodies resolve as a group — and paid O(line) per `<<`
twice. The test that would have caught P1-1 existed but used `${p##*/}`
(`p` does not end in `r`).

## P1 — Fixed

### P1-1 — `#` after a word ending in `r` opened a comment (2.6.0)

shell.cyml's `start_after = " \t\n\r;&|()<>"`; `_gp_parse_string`
decoded only `\n` and `\t` and turned any other `\X` into `X`, so the
set held the letter `r`, not CR. `b=${dir##*/}` → comment from the
first `#`; also `${var#pre}`, `for#x`. 10 of 2,091 local scripts. The
hand-coded oracle had CR, so M2 and the oracle diverged — the only
divergence in 2,400 random heredoc-free inputs.
**Fix:** `\r` decoded; a backslash before any other letter or digit
counts as a bad escape and rejects the grammar (`\$`-style punctuation
still means the byte; the only escapes any bundled grammar uses are
`\"` `\\` `\n` `\t` `\r`). Tests: `${dir##*/}`, `${var#p}`, CR as a
boundary, `\e` rejected, `\$` loads — fail on the pre-fix tree.

### P1-2 — Streaming: an arithmetic `<<` became a heredoc across a compaction

`_ds_hd_in_arith` counted `((` back to the line start **or the buffer
start**. Once a drain had committed `$((`, the next scan saw `1 << n`
with no `((` and queued a heredoc with delimiter `n`:
`y=$((1 << n))\necho a\nn\n…` split at 6–9 came back with `echo a\nn`
as a body. With no line `n` it held until finish — 19 MB after a 7-byte
first feed overflowed the 16 MiB buffer (554 failed feeds, coverage
broken).
**Fix:** the count is kept in `tokenize_with_grammar` as tokens are
emitted (operator / punctuation only — which also fixes P2-5 and P2-3)
and a depth-1 scan that ends inside an open `((` reports a hold from
it, so a drain never commits into one. The 19 MB case now peaks at a
176-byte buffer, no errors, coverage intact.

### P1-3 — Streaming: the heredoc hold bound was not enforced once the watch armed

The watch fast path returned before the `VYK_HEREDOC_HOLD_MAX` check
ran, so an unterminated `cat <<EOF` held until `VYK_STREAM_CAP`
(16 MiB) and then failed every feed: 17.8 MB in 4 KB chunks, 221
failed feeds, coverage broken, 436 MB heap.
**Fix:** a hold-start field (+144; record 144 → 152 bytes) and the
bound checked on the watch path too. The 17.8 MB case peaks at 1 MiB,
no errors. A terminated heredoc over 1 MiB fed in chunks now degrades
to code past the bound, as ADR 0023 documents — 2.6.1 kept it (by
holding without bound). Test: 1.3 MB unterminated heredoc, no feed
error, buffer ≤ 1 MiB + a chunk, full coverage — fails pre-fix.

## P2 — Fixed

- **P2-1 — Bodies lost at split offsets when the opener was "resolved"
  but its body was not.** Each opener searched for its terminator from
  its own line's end, but bodies run in order from the first top-level
  line break: `cat <<A <<B\nB\nA\n…\nB` (B's search found the `B` that
  is A's body), `cat <<EOF "a\nEOF\n"\n…` and `cat <<EOF | awk '\nEOF\n'`
  (the terminator inside a string), `cat <<EOF >a; cat <<EOF >b`. The
  H step, which searches correctly, reported no hold when it could not
  emit. **Fix:** an unemittable or unfinished group, and bodies still
  queued when the scan ends, hold from the line's first opener.
- **P2-2 — A 1-byte body was held by the marker window while its opener
  line committed** (`cat <<E\nE\necho z`, shell's 3-byte `<<<` window).
  **Fix:** the scanner reports the last fully emitted group; its tokens
  are final and skip the tail checks.
- **P2-3 — Each `<<` cost O(line), twice** (the arithmetic re-count and
  the scan to the line end): a 100 KB line of `x<<y` 10 s, 200 KB 40 s,
  a 20 KB one in 64-byte chunks 31 s. **Fix:** the running count (P1-2)
  and a one-entry line-end cache. 0.07 s / 0.14 s / 0.02 s.
- **P2-4 — A hold with no fast path re-scanned the held bytes every
  feed** (an opener line that never gets its LF: CR-only files, a giant
  line): 1 MiB in 4 KB chunks, 37 s. **Fix:** watch mode 2 — wait for
  the next line break, the only byte that can change such a verdict.
  0.38 s.
- **P2-5 — `((` inside quotes counted as arithmetic** —
  `sed -E 's/((a|b)+)c/X/' <<EOF` lost its heredoc and the body's
  apostrophe opened a string to EOF (single feed). Fixed by P1-2's
  token-driven count.
- **P2-6 — `<<END-OF-DATA` was not a heredoc** (bare delimiters were
  `[A-Za-z_][A-Za-z0-9_]*`). `-` and `.` added; a wider delimiter can
  only add heredocs whose terminator line exists.
- **P2-7 — A file named `<stdin>` was never read** (2.6.1): the CLI
  used the message name as its stdin marker — `vyk --language=shell
  '<stdin>'` exited 0 with no tokens. A flag decides now (smoke).

## P3 — Fixed

- Closed / unreadable stdin said "file not found or not readable" —
  now `cannot read standard input`.
- `--language shell` (space, not `=`) said "unknown option" — now names
  `--language=`; same for `--theme` / `--export-theme`.
- Help's exit-2 line lacked "extra FILE"; the man page said "all 45
  grammars"; `main.cyr`'s error-function list and "two-pass" parse
  comment were stale; `out.cyr` did not say EAGAIN is latched.
- Grammar loading allocated two fresh 8-byte slots per key and one per
  array element, never freed — 55,688 of `bootstrap_grammars`' 305,944
  bytes. One shared block now (−18 %, output identical on 4,500 files).
- `fuzz/chunk_invariance.fcyr` printed "15 grammars x 8 chunk sizes"
  since 2.4.0; `state.md` said chunk invariance was "15 of 20 corpora"
  (it has been 41/41 since 2.5.2).
- `tokenize.cyr`'s record-layout table stopped at offset 80 ("88 bytes
  total", record 144); two docstrings sat above the wrong functions;
  `_free` left 112..136 unpoisoned; `VYK_HEREDOC_HOLD_MAX`'s comment
  claimed every drain re-scans the hold.
- `default_scanner.cyr`'s dispatch table omitted steps H and 7c; the
  line-rule docstring sat above `_ds_byte_in`; the fail-cache and
  budget comments were stale ("linear always").
- The shell oracle's header table numbered steps the code does not
  (and sent `#` to the wrong one).
- Four corpus files had drifted from vidya since 2026-08-20 (ADR 0001
  re-sync).

## Scheduled — not fixed here

Each is in a pinned release in `docs/development/roadmap.md`.

- **P2-8 — Delimiter forms bash accepts:** `<<"E"OF`, `<<E\OF` (read as
  `E`), `<<''`, `<<!` → 2.7.1.
- **P2-9 — The terminator-search budget scales with the buffer**, so on
  pathological input (200 distinct unterminated openers after 70 KB of
  comments; five multi-line arithmetic shifts in 340 KB) a stream gives
  up sooner than a single feed → 2.8.0 (index lines, drop the budget).
- **P3 — Watch costs:** mode 2 re-scans a hold at each new line break
  (an opener followed by a string spanning many lines); the terminator
  watch resumes at the start of a long partial line (1 MiB one-line
  body in 512-byte chunks, 5.5 s). Bounded by the 1 MiB hold → 2.8.0.
- **P3 — Grammar validation:** a multi-byte heredoc `indent` uses its
  first byte; `escape` on a heredoc or line rule is accepted and
  ignored → 2.7.1.

## Not defects / kept

- A second `--export-theme=` replaces the first — last wins, as for
  every other flag.
- A non-blocking stdout gets exit 3 and truncated output — loud, as
  coreutils does; now documented in `out.cyr`.
- `tokenize_source_handcoded` has had no caller since 2.5.2 (the CLI
  uses the length-taking `_vyk_handcoded`). Kept: it ships in the
  bundle, no consumer calls it, consumer DCE strips it, and CLAUDE.md
  names it as the one surviving non-public `tokenize_source*` symbol.
- `Dockerfile.<anything>` false positives (`Dockerfile.5.gz`,
  `Makefile.cmake`) — the trade ADR 0025 records.

## Clean checks

- No out-of-bounds read or write found by review or by the probes:
  `_detect_fname` / `_detect_shebang` at every `index ± length` bound
  (41 paths, 16 shebangs), every end-of-input heredoc shape (`<<`,
  `<<-`, `<<'`, `<<"`, `<<\`, `<<''`, CRLF, terminator at EOF), stdin
  at the cap ± 1, 3,000 random argument sets (exit codes 0–4 only, no
  signals).
- The buffered writer changes no byte: identical to 2.6.0 on all 49
  corpus files × 4 output modes and 2,500 system files; every mode
  exits 3 on `/dev/full` and on a closed stdout; nothing reaches stdout
  after a failure.
- Streaming state machine: feed after finish returns −2, extra drains
  while held are harmless, finish while held matches a single feed,
  the prev-byte field survives both compaction paths.
- Memory: a stream new/free cycle leaves 5,824 bytes (the bump
  allocator; pre-existing, documented); 2.6.x adds 56 bytes of record.
