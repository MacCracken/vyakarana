# Security audit — 2026-05-09 (2.1.x closeout)

- **Scope:** vyakarana 2.1.0 → 2.1.4 changes. Surfaces added:
  seven new bundled grammars (PowerShell, Crystal, Julia, Vue,
  Svelte, Nix, Terraform); the `detect_language` length-bucket
  refactor (2.1.0); `_stream_is_trailing_complete` tightening
  (2.1.4); the `tokenbuf_drop_front` and
  `tokenize_stream_discard_consumed` primitives (2.1.4); the
  `streaming.fcyr` random-split fuzz harness (2.1.4); CSS `%`
  operator addition (2.1.1).
- **Auditor:** 2.1.5 closeout pass.
- **Trigger:** rolling cadence — surfaces added in 2.1.x are
  mostly declarative `.cyml` plus two small streaming primitives.
  The closeout audit confirms the grammar-loader hardening
  didn't regress and the discard math is bounds-safe.
- **Trust model:** unchanged. vyakarana is a library over
  arbitrary input bytes; new grammars don't expand the input
  surface; the streaming primitives operate on the same
  caller-supplied buffer + stream-internal staging tokenbuf
  that 2.0.x established.

## Surfaces reviewed

### Seven new grammars (2.1.0–2.1.3)

All seven are declarative CYML files — no Cyrius code. They're
parsed by the existing `_gp_parse` loader (audited at the
2026-04-23 pre-1.0 audit and again at the 2026-05-09 1.13
closeout when the embedded blobs landed). The loader's
bounds-checking (rejecting unbounded extension-list lengths,
NUL-terminating buffers, etc.) handles all input shapes the
2.1.x grammars supply.

Specific verifications:

- **PowerShell** (`grammars/powershell.cyml`) — `special_vars
  = false` was a deliberate design call (so `$args` tokenizes
  as one ident); verified the documented behaviour matches
  the cmdlet-style `Get-Process` ident pattern. Pair-rule
  `<#…#>` block comment uses backtick (byte 96) as the escape
  for the double-quoted-string pair — the loader accepts the
  byte; the scanner reads it via `pair_rule_escape`. Bounds
  unaffected.
- **Crystal** (`grammars/crystal.cyml`) — `?` and `!` in
  `ident_cont` are non-control bytes; no parser surprises.
- **Julia** (`grammars/julia.cyml`) — block comment `#=…=#`
  expressed as a pair rule alongside the `#` line comment
  expressed as a pair rule with `end = "\n"` (avoids the
  pair-vs-line-prefix collision documented in arch note 003,
  same shape as Lua). Backtick command literal `\`…\``
  uses standard pair shape.
- **Vue / Svelte** (`grammars/vue.cyml`,
  `grammars/svelte.cyml`) — both use the existing compose
  rule (ADR 0013) for `<script>` → JS and `<style>` → CSS.
  Vue deliberately omits a `<template>` compose rule (would
  drop Vue's own `@`/`#` operators in template content);
  documented in the grammar header. No new compose-rule
  semantics.
- **Nix** (`grammars/nix.cyml`) — `'` and `-` in `ident_cont`
  match the Haskell-prime / kebab-case patterns. `''…''`
  indented-string pair rule has `slen = elen = 2` — the
  same-byte-marker case is now defended by FINDING-010's
  trailing-complete tightening. Verified no related issue.
- **Terraform** (`grammars/terraform.cyml`) — both `#` and
  `//` line rules; the line scanner checks the full marker
  length so `/*` doesn't collide with `//`. Standard CYML
  shape.

**No findings** on the new grammars.

### `detect_language` length-bucket refactor (2.1.0)

Splitting one function with 80+ returns into four helpers
(`_detect_short`, `_detect_4byte`, `_detect_5plus`,
`_detect_basename`) preserves the first-match-wins ordering
of the original. Each helper returns `0` when no extension
in its bucket matches; `detect_language` calls them in
order and short-circuits on the first non-zero return.

Verified:
- The helpers cover the full extension set from the
  pre-refactor implementation. No paths regressed.
- `_detect_combined` (the asm-flavour-vote path) still works
  unchanged because it calls `detect_language` and then
  optionally rescans content for asm.
- `tests/vyakarana.tcyr` 1.11.2 detection probes still pass
  unchanged.

**No findings.**

### `tokenbuf_drop_front` (2.1.4)

Five-line primitive in `src/token.cyr`:

```cyrius
fn tokenbuf_drop_front(tb, n) {
    if (n <= 0) { return 0; }
    var count = load64(tb + 8);
    if (n >= count) {
        store64(tb + 8, 0);
        return 0;
    }
    var keep = count - n;
    var data = load64(tb);
    var src = data + n * TOKEN_SIZE;
    var bytes = keep * TOKEN_SIZE;
    var i = 0;
    while (i < bytes) {
        store8(data + i, load8(src + i));
        i = i + 1;
    }
    store64(tb + 8, keep);
    return 0;
}
```

Bounds review:
- `n <= 0` early-exit. Safe.
- `n >= count`: clamp to "drop all," set count=0. Source/dest
  pointers never dereferenced. Safe.
- After clamps, `0 < n < count`, so `keep = count - n > 0`.
- `bytes = keep * TOKEN_SIZE`. `keep < count`, and the
  tokenbuf's `byte_cap` is `>= count * TOKEN_SIZE` by
  construction (push grows it). So `bytes <= byte_cap` — the
  `store8(data + i, …)` and `load8(src + i)` reads stay within
  the allocated buffer.
- Source `data + n * TOKEN_SIZE` and dest `data` overlap when
  `n < keep`; forward byte copy is correct in this direction
  (src ahead of dst, so reading src[i] before writing dst[i]
  doesn't clobber unread bytes).
- Updates `count` to `keep`. The shifted-out tail bytes
  (between `keep * TOKEN_SIZE` and `count * TOKEN_SIZE`) are
  not zeroed but no longer accessible via accessors (they're
  past the new count).

**No findings.** The primitive is small enough that I'd
ship it without a guard, but the existing `n <= 0` and
`n >= count` clamps both make sense as defensive shape-
matching against the rest of the tokenbuf API.

### `tokenize_stream_discard_consumed` (2.1.4)

Wrapper over `tokenbuf_drop_front`:

```cyrius
fn tokenize_stream_discard_consumed(s) {
    if (s == 0) { return 0; }
    var staging = load64(s + 56);
    var consumed = load64(s + 64);
    if (consumed <= 0) { return 0; }
    tokenbuf_drop_front(staging, consumed);
    store64(s + 64, 0);
    return consumed;
}
```

- Null-safe on `s == 0`.
- `consumed <= 0` no-op. Safe (matches drop_front's behaviour
  but short-circuits to avoid the inner alloc/copy work).
- `staging` is the stream's internal tokenbuf, allocated in
  `tokenize_stream_new`. Cannot be 0 unless `_free` was called
  (which zeroes the field) — a use-after-free pattern.
  `tokenbuf_drop_front(0, n)` would crash on `load64(tb + 8)`.

**Defensive check missing on `staging == 0`** — not filed
as a finding because (a) it's strictly a use-after-free, which
the user controls, and (b) it would crash loudly at the load
rather than silently corrupting state. Still worth a one-line
guard. Pulled into the recommendations below.

### `_stream_is_trailing_complete` tightening (2.1.4)

Pre-2.1.4: the trailing-complete heuristic checked
`memeq(buf + tail - elen, endp, elen)` to verify the closing
marker was at the tail. For same-byte pair rules
(`"…"`, `'…'`, `\`…\``), this check matched the open quote
against itself — committing a 1-byte string as "complete."
Streaming would then commit the open quote; the actual close
on the next feed would open a SECOND string.

Fix: require `t_len >= slen + elen` (minimum complete length
for any pair rule) before applying the closing-marker check.

The fix is conservative — it can only delay commits, not
emit wrong tokens. The `tests/vyakarana.tcyr` 2.0.x
streaming probes all still pass; the new 2.1.4
`split-after-opening-quote` probe locks the regression
against return.

**FINDING-010 (LOW, fixed in-pass).** `_stream_is_trailing_complete`
over-eager on same-byte pair markers; fixed by minimum-
complete-length check.

### Compose-rule START markers split across chunks (2.1.4)

Caught by the new `streaming.fcyr` random-split harness when
exercising HTML, but identified as a real streaming bug, not
a fuzz artifact. When a chunk boundary lands inside a
compose-rule start marker (e.g., between `<` and `style>`),
the leading byte commits as a 1-byte token before the rest
of the marker arrives, so the compose rule never matches.

The fix needs compose-aware prefix buffering — the scanner
has to hold trailing bytes that match a prefix of any
compose-rule start marker. Out of scope for 2.1.x; filed for
the next streaming-opt cut.

**FINDING-011 (LOW, deferred).** Compose-rule streaming
prefix gap. HTML / Vue / Svelte / Markdown random-split fuzz
cases skipped in `streaming.fcyr` until the fix lands.
Single-shot tests in `tests/vyakarana.tcyr` continue to
cover compose correctness for whole-buffer inputs.

### CSS `%` operator (2.1.1)

One-byte addition to `grammars/css.cyml`'s operator list.
Surfaced when the Vue corpus exercised `width: 100%;`
inside a `<style>` block routed through CSS. Without `%`
in operators, the byte fell through to TK_ERROR.

**No findings.** Pure additive fix to a documented gap.

## Recommendations

1. **Add a defensive `staging == 0` check in
   `tokenize_stream_discard_consumed`.** One-line guard
   matching the pattern used elsewhere. Out of scope for
   2.1.5 (audit-only cut); fold into the next opt cut.
2. **Compose-rule prefix buffering** (FINDING-011). The
   tracked work for the next streaming-opt cut. Should
   re-enable the HTML / Vue / Svelte / Markdown cases in
   `streaming.fcyr`.
3. **Revisit the 1.13.0 binary-size soft cap.** The 300 KB
   target predates ADR 0014's embedded-grammar design and
   is now consistently exceeded as grammars are added. Not
   a security concern; consider raising to 500 KB or
   removing entirely as a 2.x roadmap item.
4. **Toolchain pin discipline.** During 2.1.4 the local
   `~/.cyrius/current` drifted from 5.10.0 → 5.10.4
   mid-session, surfacing test failures that were resolved
   by `cyriusly use 5.10.0`. The pin is authoritative; CI
   downloads exactly the pinned version's tarball. The
   memory file `feedback_cyrius_pin_authority.md` captures
   this — agents working on the cyrius dev box should
   verify `cyrius --version` matches `cyrius.cyml`'s pin
   before reporting a regression.
5. **Next audit:** the next streaming-opt cut (which fixes
   FINDING-011). Surface change is the new compose-prefix
   buffering machinery; bounds review needed there.
