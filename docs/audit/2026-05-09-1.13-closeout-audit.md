# Security audit — 2026-05-09 (1.13.x closeout)

- **Scope:** vyakarana 1.12.0 → 1.13.2 changes. Surfaces added:
  fuzz harnesses (1.12.0); `theme_export_helix` /
  `theme_export_iterm` (1.12.1); benchmark suite (1.13.0); CLI
  error functions split (1.13.1); man page (1.13.1); compose-
  fenced rule type + scanner step 0b (1.13.2); toolchain pin
  bump 5.9.36 → 5.10.0 (1.13.2). Reviewed against the
  CLAUDE.md §Hardening 8-point checklist; baseline is the
  2026-05-09 1.11-closeout audit.
- **Auditor:** 1.13.3 cut hardening pass.
- **Trust model:** unchanged from the pre-1.0 baseline.
  vyakarana is a library over arbitrary input bytes. CLI
  inputs: `vyk` argv, file contents (capped at
  `VYK_SRC_CAP` = 1 MB), grammar blobs (embedded; capped at
  `GRAMMAR_FILE_CAP - 1` = 32,767 B per FINDING-007). No
  network I/O, no shell-out, no arbitrary writes.

## Surfaces reviewed

### `src/theme_export.cyr` Helix + iTerm emitters (1.12.1)

Both new emitters mirror `theme_export_vscode`'s shape:
read-only walk over the kind table, format strings emitted to
stdout via `print`. No reads from caller-supplied bytes; no
allocation; the format strings are compile-time literals with
no escape-injection surface. The iTerm emitter's
`_te_iterm_chan` performs a `byte_value → "0.0"`-style float
literal lookup with a fall-through "0.5" for unanticipated
values. The fall-through is unreachable today — the bundled
themes use a fixed palette of 6 byte values — but a future
theme adding a non-canonical channel would silently produce a
slightly-wrong colour rather than a crash.

**No findings.**

### `tests/bcyr/vyakarana.bcyr` (1.13.0)

Test artifact only. Inputs are compile-time string literals;
the `setup()` step is the same `tokenize_source("", lang)`
bootstrap pattern as the test suite. Not part of the runtime
surface — `cyrius bench` builds and runs it standalone, not
linked into `vyk` or the bundle.

**No findings.**

### `src/main.cyr` error-message split (1.13.1)

Three new error functions — `unknown_option_error`,
`bad_value_error`, `extra_arg_error` — plus the rewritten
`io_error` and `no_grammar_error`. Each uses
`_sanitize_for_stderr` (the existing FINDING-006 mitigation
from 2026-04-23) to strip control bytes from echoed argv.
Allowed-values strings (`"default, dark, none"`,
`"vscode, helix, iterm"`) are compile-time literals; argv
bytes get sanitized; stderr formatting uses the same
fixed-prefix shape as before.

The risk vector that *could* exist here — argv echoed
verbatim → ANSI escape injection → terminal exploitation —
is closed by `_sanitize_for_stderr` replacing every byte
< 0x20 (incl. ESC) and 0x7F with `?`.

**No findings.**

### `docs/man/vyk.1` (1.13.1)

Static groff source. Not part of the runtime surface; renders
to stdout via `groff` or `man`. No shell substitution, no
includes, no embedded content from external sources.

**No findings.**

### `match = "compose_fenced"` rule type (1.13.2)

The most substantial 1.13.x surface addition — new scanner
step 0b in `tokenize_with_grammar`, new rule type at the CYML
loader, new struct, new helpers. Reviewed in detail:

- **`_ds_try_compose_fenced_rules` bounds.** Outer rule loop
  walks `compose_fenced_rules` (vec of size N). For each
  rule:
  - `i + slen <= src_len` guard before the start-marker
    `memeq`. Safe.
  - `_ds_scan_tag` walks `[start, src_len)` while
    `_ds_is_tag_byte(load8(src + p))` — bounded by
    `src_len`.
  - `_ds_scan_to_lf` walks `[start, src_len)` looking for
    LF — bounded by `src_len`.
  - `_ds_find_fenced_close` walks `[body_start, src_len)`
    with the `j + elen <= src_len` guard inside its loop.
    Safe.
  - The captured-tag scratch buffer is
    `alloc(tag_len + 1)`. `tag_len = tag_end - tag_start`,
    where both are bounded by `src_len`. Worst-case
    `tag_len ≈ src_len` if the entire input is tag bytes
    after the marker. That's a 1 MB alloc max (one of the
    existing `VYK_SRC_CAP`-sized allocations); fine.
  - The byte-by-byte copy into the scratch buffer is
    bounded by `tag_len`. Safe.
  - Recursion via `tokenize_with_grammar(inner_g,
    src + body_start, body_len, inner_tb)` shifts the
    `src` pointer; `body_len` is bounded; the inner
    grammar can't read outside `body_len` bytes because
    its own scanner uses `src_len` as the upper bound.

- **Recursion depth.** `tokenize_with_grammar` calls
  `_ds_try_compose_fenced_rules` (and `_ds_try_compose_rules`)
  which can call `tokenize_with_grammar` recursively. Real-
  world depth bounded by markdown nesting in the source —
  CommonMark doesn't permit nested fences inside the same
  fence (the closing ``` ` ` ` ` ``` would terminate the
  outer one), so depth is effectively 1 for the markdown
  use case. The 1.12.0 stress probe (`6× adjacent compose`)
  exercises sequential compose, not nested; a hand-crafted
  input with a markdown fence containing HTML containing
  `<style>` could reach depth 3 (markdown → html → css).

- **Fall-through behaviour.** `result == 0` paths (no
  start match, no LF, no close) all return 0 and let the
  outer pipeline handle the cursor. No cursor advance
  without a complete match. Coverage invariant preserved.

- **Tag-character class.** `_ds_is_tag_byte` accepts
  `[A-Za-z0-9_+-]`. Closed set; `registry_find_by_name`
  performs `streq` over a known list. No risk of grammar
  injection via crafted tag bytes — unrecognized tags fall
  back to `TK_STRING`.

**No findings.**

### Toolchain pin: `cyrius = "5.10.0"` (1.13.2)

Pin bumped from 5.9.36 because the local 5.10.0 toolchain's
stdlib drift made 5.9.36 unbuildable on systems with the
newer cyrius installed. CI's release-tarball install step
(`grep 'cyrius *= *"' cyrius.cyml | head -1`) automatically
picks up the new pin. No security implications — strictly a
build-toolchain compatibility decision.

**No findings.**

## Fuzz / stress / lint posture (1.13.2)

- **Fuzz:** 3/3 harnesses pass on every CI run. The
  `tokenize.fcyr` random-byte sweep × 6 grammars × 3 sizes ×
  16 iters covers the compose / compose_fenced step paths
  for every grammar that could carry such a rule — no
  invariant breaks observed.
- **Stress:** 10 tcyr probes in the 1.12.0 group plus 13
  more in the 1.13.2 group. Pathological backtracking,
  unclosed fences (compose AND compose_fenced), nested
  compose, broken UTF-8, 4 KB ident run. All preserve the
  coverage invariant.
- **Lint + fmt:** mandatory pre-release per CLAUDE.md
  §Gates. CI's `Lint + fmt` step runs `scripts/lint-fmt.sh`
  (cyrius lint → 0 warnings; cyrius fmt --check → no drift)
  on every PR.

## Recommendations

1. **No code changes.** This audit found nothing actionable.
   1.13.x surface additions are clean.
2. **Pin verification on next major.** When 2.0.0 ships, the
   first audit should confirm the streaming-tokenizer changes
   don't introduce new buffer-bound assumptions that the
   existing FINDING-002/003/004 mitigations weren't designed
   for. Streaming changes the bound semantics from "single
   `alloc(N)` then read" to "callee provides chunks" — worth
   a dedicated review.
3. **Consider a corpus-fuzz harness for 1.14+.** Today's
   fuzz harnesses use random bytes; a corpus-replay harness
   that mutates real source files (vidya snapshots) would
   catch shape-specific regressions that random bytes miss.
   Out of scope for 1.13.x; flagged here for the post-2.0
   queue.
