# vyakarana — distribution paths

How vyakarana ships, who consumes which artifact, and what the
release flow actually does. Documented at the 1.13.3 cut as the
last pre-2.0 housekeeping; future agents and packagers should
trust this over inferring from `cyrius package` (still stubby
upstream — needs more ark work first; see §`cyrius package`
status below).

---

## Two paths in current use

vyakarana publishes **two** distribution artifacts on every
release tag. Different consumers, different formats, different
trust models.

### 1. Single-file source bundle (`dist/vyakarana.cyr`)

The artifact downstream Cyrius projects pull via `cyrius deps`.

- **Format:** one concatenated Cyrius source file containing
  every `[lib] modules` entry from `cyrius.cyml`. As of 2.3.0
  this is `src/token.cyr` + `src/grammar_blobs.cyr` (45 inlined
  grammars per ADR 0014) + `src/grammar.cyr` +
  `src/grammars/default_scanner.cyr` + `src/grammars/shell.cyr` +
  `src/tokenize.cyr` + `src/detect.cyr` + `src/lsp.cyr`.
  348,582 bytes (340.4 KB), 4,030 lines by `wc -l`. **`cyrius
  distlib` misreports the same file as 4002 lines** — its own
  counter is wrong, not the bundle; trust `wc -l` when checking
  drift by eye.
- **Generated by:** `cyrius distlib` (toolchain command). Reads
  `[lib] modules` order, concatenates, writes to
  `dist/vyakarana.cyr`. Order matters — Cyrius is single-pass.
  **Run `sh scripts/embed-grammars.sh` first.**
  `src/grammar_blobs.cyr` is generated and gitignored, so on a
  fresh checkout it is simply absent — and as of cyrius 6.2.52
  `distlib` fails loud (exit 1) on a missing `[lib] modules`
  entry instead of quietly concatenating what it can find. That
  is the workflow change worth internalizing: skipping the embed
  step used to hand you a bundle with all 45 grammars silently
  missing, and now it stops you. The same toolchain window also
  raised distlib's per-module read cap from 256 KB to 1 MB;
  `src/grammar_blobs.cyr` is 204,240 bytes — 78% of the old cap
  — so that headroom was not theoretical.
- **Committed:** yes. CI's `distlib drift check` step diffs the
  committed bundle against a fresh `cyrius distlib` and fails
  the merge on drift.
- **Consumed by:** any downstream Cyrius project. Pin a tag in
  `cyrius.cyml`:

  ```toml
  [deps.vyakarana]
  git     = "https://github.com/MacCracken/vyakarana.git"
  tag     = "2.3.0"
  modules = ["dist/vyakarana.cyr"]
  ```

  `cyrius deps` clones the tag, copies the bundle into the
  consumer's `lib/`. The consumer's own `[deps] stdlib` list
  resolves the standard-library symbols the bundle references
  (`alloc`, `streq`, `vec_*`, `print`, etc.).
- **Self-contained?** For grammar definitions yes (45 grammars
  inlined as Cyrius string literals; ADR 0014). For stdlib no —
  the consumer supplies it.
- **Pin compatibility:** the public API names + arg orders in
  the bundle are stable across the entire 2.x line — the
  streaming primitive (`tokenize_stream_*`) is the contract.
  The 1.x synchronous `tokenize_source(src, lang)` entry was
  removed in 2.0.0 (ADR 0017); 1.x and 2.x consumers cannot
  share a pin. See `docs/architecture/overview.md` "Frozen
  public contracts."
- **First version that worked:** 1.11.1. Earlier tags called
  `file_read_all("grammars/<name>.cyml")` at runtime; only the
  bundle file was vendored, so consumers got an empty
  tokenizer. **2.x consumers pin ≥ 2.0.0;** 1.x consumers
  pin ≥ 1.11.1.

### 2. Release tarball (GitHub Releases)

The artifact end-users and packagers download to get a runnable
`vyk` binary.

- **Format:** `.tar.gz` archive named
  `vyakarana-<VERSION>-<TARGET>.tar.gz` (e.g.
  `vyakarana-2.3.0-x86_64-linux.tar.gz`). Contains:
  - `vyk` — DCE'd binary built with `cyrius build` and
    `CYRIUS_DCE=1`.
  - `grammars/` — all 45 `.cyml` source files (also embedded
    in the binary; included on disk for grammar authors who
    want to edit and re-run with `vyk path/to/foo.cyml`).
  - `dist/vyakarana.cyr` — the source bundle (so a downloader
    can vendor it without git-cloning the whole repo).
  - `README.md`, `LICENSE`, `CHANGELOG.md`, `VERSION` —
    metadata.
- **Built by:** `.github/workflows/release.yml` on every
  semver tag push (`[0-9]*`). Targets today:
  `x86_64-linux`. arm64 / macOS pending toolchain availability.
- **Verified by:** local CI gate (full `ci.yml` run before any
  release artifact is built). SHA256 sums per artifact in
  `SHA256SUMS` alongside the tarballs.
- **Verified locally (1.13.3):** the same tarball-creation
  steps from `release.yml` were walked through manually
  against `build/vyk` 1.13.2 — extracted binary runs
  (`vyk --version` → `vyk 1.13.2`), grammars/ + dist/ +
  README + LICENSE all present. ~210 KB compressed.
  Bundle layout has been stable since; 2.3.0 ships the same
  shape with the post-1.x grammars and streaming primitive
  added.
- **Source tarball:** the workflow also publishes
  `vyakarana-<VERSION>-src.tar.gz` via `git archive` so a
  downloader can build from source without cloning git.

## How a consumer chooses

| Consumer                                      | Use                          |
|-----------------------------------------------|------------------------------|
| Another Cyrius project (owl, cyim, vidya, …)  | dist/vyakarana.cyr (path 1)  |
| End-user wanting `vyk` on their PATH          | release tarball (path 2)     |
| OS packager (zugot, deb, rpm, …)              | release tarball (path 2)     |
| Grammar author editing a single `.cyml`       | release tarball, then run `vyk path/to/foo.cyml` against the disk file |

A downstream Cyrius project that **also** wants a built `vyk`
binary (for CI tooling, for example) can reference both: pin
the dep for the library and download the tarball separately.

## `cyrius package` status

The toolchain ships a `cyrius package` subcommand whose help
text still says "create .ark distributable". The old note here
was pinned to cyrius 5.10.0 and a full major line stale, so it
was re-checked by hand under **6.5.4 on 2026-07-31**: still
unusable, just differently so. It compiles the `[build]` entry
(`src/main.cyr`) — not the `[lib] modules` set — and does not
prepend `[deps] stdlib`, so it reports 17 reachable undefined
functions (`alloc`, `streq`, `vec_*`, `print`, `args_init`, …)
and refuses to emit a binary at all. Which release turned that
refusal on for this path was not pinned down — a bare reachable
undefined call still only warns under 6.0.3, 6.1.24 and 6.5.4
alike, so `package` is reaching the stricter gate by some route
of its own. The 5.10.0 failure mode (a `build/main` that
SIGILLs at runtime on the unresolved symbols) is therefore gone;
what replaced it is a run that prints `package ready in build/`,
**exits 0**, and leaves no new artifact in `build/`. No `.ark`
output either way; the format and manifest are still unspecified
upstream.

Until that lands, **don't use `cyrius package` for vyakarana**,
and in particular don't gate CI on its exit status — it returns
0 on the failure path, so a green exit proves nothing.
The two paths above are the canonical distribution surfaces;
they cover every consumer we know about. When `cyrius package`
matures, this doc and `state.md` should pick it up — likely as
a third additive path rather than a replacement (it doesn't
overlap exactly with either of the existing two).

## Release procedure (operator)

The repo owner runs the release flow when shipping a new minor
or patch:

0. **Toolchain + stdlib prep.** As of 2.2.2 the stdlib `lib/` is
   gitignored (ADR 0018), so a clean clone has no stdlib until
   `cyrius deps` populates it from the version-matched toolchain
   snapshot. Run `cyriusly use "$(grep '^cyrius = ' cyrius.cyml
   | sed 's/.*"\(.*\)"/\1/')"` then `cyrius deps && sh
   scripts/embed-grammars.sh` before the gate sweep. CI does the
   same via the upstream installer + `cyrius deps`. On an
   *existing* working copy that is not enough: `cyrius deps`
   treats an already-populated `lib/` as satisfied and never
   refreshes it, so after a pin bump you must `rm -rf lib &&
   cyrius deps` or the whole sweep runs against the previous
   toolchain's vendored stdlib. Consumers re-pinning vyakarana
   hit the same trap on their own `lib/`.
1. **Final gate sweep on the release branch.** All five gates
   green: `cyrius build`, `cyrius test`, `sh scripts/smoke.sh`,
   `sh scripts/lint-fmt.sh`, `cyrius fuzz`. Plus
   `cyrius bench tests/bcyr/vyakarana.bcyr` if a perf-touching
   change shipped.
2. **Doc sync.** CHANGELOG `[Unreleased]` collapsed into the
   version header; `state.md` Current-status block matches
   reality; ADRs filed if the cut introduced new public
   surfaces.
3. **Tag.** `git tag <VERSION>` then `git push origin <VERSION>`.
   `release.yml` triggers on the tag push, runs the full
   `ci.yml` first (gate), then builds + packages + creates
   the GitHub release.
4. **Verify after publish.** Download the tarball from the
   release page; extract; run `vyk --version`. Should match
   the tag.

The agent (Claude Code) does not run `git tag` or `git push` —
the user owns all git operations per CLAUDE.md.
